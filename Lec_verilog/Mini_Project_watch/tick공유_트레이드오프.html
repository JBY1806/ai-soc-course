100 Hz tick 공유 — 자원 vs 시작 정확도

대상: verification_v2/source_file (정안성 10/16 20:14 포트 통일판) · 2026-10-16 · 정보윤. 측정 · 정리는 함. 같은 비교를 그 전 판(merged_v4)에서 먼저 했고 그 숫자는 Vivado GUI 로 직접 확인함 — 아래 v2 숫자는 같은 스크립트로 다시 잰 값(FF 는 두 판이 같고 LUT 만 10~20 작음).

결정 (10/17, 정안성 · 정보윤 디스코드): ④ 절충안으로 간다 — 100 Hz tick 은 시계 · 스톱워치 · 타이머가 각자(스톱워치 · 타이머 것은 RUN 순간부터 셈), 4 kHz 는 그대로 공유. 팀 코드(verification_v2/source_file)에 반영: tick_gen_100hz_run.v + Top 의 U_TICK_GEN_SW · U_TICK_GEN_TM. 팀 코드로 다시 잰 값: LUT 355 · FF 228 · WNS +3.837 ns (아래 ④ 행과 같음, 구현 후 · 배치). 10초 타이머 = 10,000 ms + 20 ns.
원래 정할 것이었던 문제: 지금 판처럼 100 Hz tick 하나를 시계 · 스톱워치 · 타이머가 같이 쓸지, 스톱워치 · 타이머만 자기 tick 을 둘지. 어느 쪽이든 발표 고찰에 같은 숫자로 말하면 됨.

무슨 일이 생기나

  • 지금 판은 U_TICK_GEN_100HZ 하나가 항상 10 ms 박자로 돌고, 스톱워치 · 타이머는 "동작 중일 때만" 그 tick 을 받음.
  • 그래서 시작 버튼을 박자 중간에 누르면 첫 1/100초가 10 ms 가 아니라 0 ~ 10 ms 사이 아무 때나 바뀜.
  • 시뮬 실측(v2 소스, Top TB): 타이머 시작 → 첫 감소 8 / 5 / 2 ms (리셋 뒤 시작 시각만 3 ms 씩 바꿈). 10초 타이머 → 9,998 ms 에 알람(tb_tm_2).
  • 시계는 영향 없음(리셋부터 같은 박자). 스톱워치도 같은 이유로 최대 10 ms(tb_sw_1 P2 가 1.000 초에 99~100 카운트를 허용하는 이유).
