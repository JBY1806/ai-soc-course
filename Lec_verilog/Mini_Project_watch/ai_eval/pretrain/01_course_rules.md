# 사전학습 1 — 수업에서 배운 설계 규칙 (김창형 교수님 Verilog 과목, 2026-09-30 ~ 10-16)

> 초안: 정보윤의 수업 기록(Lec_verilog/.md, 학습노트)에서 옮김. 정보윤이 읽고 빼거나 더할 것.
> 평가 에이전트는 이 문서를 "이 수업에서 맞는 설계"의 기준으로 쓴다.

## 1. 코딩 기본
- 모든 모듈 맨 위에 `` `timescale 1ns / 1ps `` (하나라도 빠지면 xsim elaborate 오류 XSIM 43-4099).
- 순차 always(`posedge clk`) 는 `<=`, 조합 always(`@(*)`) 는 `=`.
- 리셋: 비동기 positive 리셋(`always @(posedge clk, posedge rst)`), 보드 BTNC.
- 2진 · 16진 숫자는 4자리마다 `_` (예 `8'b1100_0000`).
- 배운 문법만 쓴다. task · function 은 수업에서 안 배움(쓰지 않는 것이 이 수업의 규칙).

## 2. FSM (6일차 · 7일차)
- 3블록 구조: ① 상태 레지스터(순차) ② 다음 상태 조합회로(Next State CL) ③ 출력 조합회로(Output CL). 합친 always 도 동작은 같지만 수업 기본은 분리형.
- 블록도에서 c_state 가 Next State CL 로 되돌아가는 피드백 선이 있어야 한다(HW5 피드백).
- 무어(Moore): 출력이 상태만으로 결정. 밀리(Mealy): 상태 + 현재 입력. 밀리 출력은 입력이 바뀌는 시점에 따라 폭이 달라진다.
- **래치 방지**: 조합 always 첫 줄에 기본값 — `n_state = c_state;`, 출력 = 0. case 에 default. 기본값이 없으면 Synth 8-327 경고와 LDCE(래치)가 생긴다(HW4-2 실제 경험: 래치 2개 → 첫 줄 기본값으로 0개).
- 상태 레지스터 외의 상태(예: mode_reg)도 레지스터로 두고 블록도에 피드백을 그린다.

## 3. 클럭 · tick (4 · 5 · 8일차)
- 보드 클럭 100 MHz 하나만 클럭으로 쓴다. 분주한 신호를 다른 FF 의 클럭으로 쓰면 파생 클럭 → 구현 Methodology TIMING-17 경고.
- 권장: tick_gen 이 1클럭 폭 펄스(tick)를 만들고, 카운터는 `if (i_tick)` 로 그 클럭에만 움직인다(CE = tick).
- 스톱워치·시계의 기본 tick = 100 Hz(10 ms, 1/100초 자리).

## 4. 버튼 디바운서 (7 · 8일차)
- 8비트 시프트 레지스터에 버튼을 넣고 8칸이 모두 1 이면 눌림(AND8) → 엣지 검출로 1클럭 펄스.
- 100 MHz 로 바로 샘플하면 8클럭 = 80 ns 라 ms 급 접점 튐을 못 거른다 → 샘플 클럭을 낮춘다(수업 1 MHz, 팀 통합판 4 kHz = 8칸 2 ms).
- 알려진 약점: AND 만 쓰면 누른 채 한 번 끊겨도 다시 1 이 되면 두 번 인식. 히스테리시스(모두 0 이어야 꺼짐)로 막을 수 있다.
- 스위치에는 디바운서를 쓰지 않는다(9일차 교수님). 비동기 입력이라 2단 FF 동기화가 정석(6일차 메타스테이블 · CDC).

## 5. 검증 (김창형 교수님 9일차 요구)
- Top 전체 시뮬레이션 기준. 10 ms tick, 분 · 시 넘어감, 안 되는 경우까지 보여 준다.
- **클럭을 올리거나 1시간을 통째로 돌리지 않는다**(초기값 조정은 허용). 팀 규칙: tick 주파수를 올리지 않고 실제 시간으로.
- 자동 판정 TB: err 카운트, `if (x !== exp)`, FAIL 출력, 마지막에 `TOTAL MISMATCH = n`.
- 트러블슈팅은 현상 → 원인 → 해결 → 결과 + Before/After 수치.
