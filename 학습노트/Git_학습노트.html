1. Git이 뭐야

Git이 뭔지 한 줄로?
내 폴더의 "버전 기록" 도구다. 작업하다가 "여기까지 저장"을 찍어두면 언제든 그 시점으로 돌아갈 수 있고, 누가 언제 뭘 바꿨는지 전부 남는다.
게임 세이브 포인트. 한 판 하다가 세이브를 찍고, 망하면 그 세이브로 돌아온다. Git은 코드 폴더에 세이브 포인트를 찍는 도구다.
Git이랑 GitHub는 뭐가 달라?
Git은 내 PC에 설치된 프로그램이고, GitHub는 그 기록을 인터넷에 올려두는 사이트다. Git만 써도 되지만, 그러면 기록이 이 PC에만 있어서 PC가 초기화되면 같이 사라진다. GitHub에 올려야 백업이 되고, 남에게 보여줄 수도 있다.
GitGitHub
어디에내 PC인터넷(구글 드라이브 같은 것)
역할버전 기록을 만든다그 기록을 보관하고 공개한다
없으면버전 기록 자체가 없음백업이 없고, 포트폴리오로 못 보여줌
왜 배워야 해?
회사에서 코드는 전부 Git으로 관리한다. 반도체 설계(Verilog)도 마찬가지다. 신입이 Git을 못 쓰면 첫날부터 막힌다. 그리고 GitHub 주소 하나로 "내가 7개월간 뭘 했는지"를 보여줄 수 있어서 취업용 포트폴리오 자체가 된다. 강사님이 미리 해보라고 한 이유가 이거다.

3. 처음 한 번만 하는 설정

왜 이름과 이메일을 알려줘야 해?
커밋마다 "누가 했는지"가 남기 때문이다. 한 번 설정하면 계속 쓴다. 이 PC는 공용이라 이 폴더에만 적용되게 한다(--global을 붙이지 않는다).
git config user.name "이름 또는 GitHub 아이디"
git config user.email "boyun1806@gmail.com"
확인: git config user.name 을 치면 방금 넣은 이름이 나온다.
git init은 뭘 한 거야?
폴더 안에 숨김 폴더 .git을 만들어서 "지금부터 이 폴더의 변경 이력을 기록하겠다"고 켠 것이다. 기존 파일은 하나도 지워지거나 바뀌지 않는다. "초기화"라는 번역 때문에 뭔가 지우는 것처럼 들리지만 아니다. 이미 완료했으니 다시 칠 필요 없다.
.gitignore는 뭐야?
"이 파일들은 기록에서 빼라"는 목록이다. 파일을 지우는 게 아니라 Git이 못 본 척하게 하는 것이다. 설치파일(exe), 데이터셋(zip), 모델(onnx)처럼 크고 다시 받을 수 있는 건 뺀다. GitHub는 파일 하나가 100MB를 넘으면 아예 거부한다.
내가 직접 쓴 .py, .ipynb, .md만 올라가면 된다. 강사가 준 원본은 안 올려도 된다.
브랜치 이름을 main으로 바꾸라던데?
Git 기본 이름은 master인데 GitHub 기본 이름은 main이다. 맞춰두면 나중에 헷갈릴 일이 없다. 첫 커밋을 하기 전이라도 상관없다.
git branch -M main

커밋 메시지는 어떻게 써?

미래의 내가 봤을 때 "아 그거" 하고 알 수 있으면 된다. 한국어로 써도 된다.
git commit -m "딥러닝 1일차: 퍼셉트론, 선형회귀 예제 실습"
git commit -m "파이썬 모듈/패키지 실습 정리"
git commit -m "CLAUDE.md, .gitignore 추가"
-m 뒤에 따옴표를 빼먹으면 편집기가 열리면서 멈춘다. 그럴 땐 Esc 누르고 :q! 치고 Enter로 빠져나온 뒤 다시 치면 된다.
지금 순서대로 쳐본다. 3번 설정을 먼저 했다면 아래 4줄이 첫 커밋이다. 
git add .
git status          ← 파일들이 초록색 "Changes to be committed"로 바뀌었는지 확인
git commit -m "과정 시작: 파이썬 1주차, 딥러닝 실습 파일 정리"
git status          ← "nothing to commit, working tree clean" 이 나오면 성공

5. git status 읽는 법

가장 많이 보게 될 화면이다. 나오는 문장별로 뜻을 알아두면 무서울 게 없다.

오늘 본 화면 (첫 커밋 전)

On branch master              ← 작업 줄기 이름. main으로 바꾸면 여기가 main이 된다
No commits yet                ← 저장을 한 번도 안 찍었다
Untracked files:              ← Git이 아직 지켜보지 않는 파일들
        .gitignore
        CLAUDE.md
        Lec_python/           ← 폴더 통째로 표시됨. 제외한 zip/exe는 안 보이는 게 정상
nothing added to commit       ← 장바구니가 비어 있다

앞으로 보게 될 문장들

문장뜻할 일
Untracked files새로 만든 파일. Git이 모른다git add .
Changes not staged for commit / 빨간색 modified있던 파일을 고쳤는데 장바구니에 안 담았다git add .
Changes to be committed / 초록색장바구니에 담겼다. 커밋 준비 끝git commit -m "..."
nothing to commit, working tree clean바뀐 게 없다. 전부 저장됐다없음. 좋은 상태
Your branch is ahead of 'origin/main' by 1 commit커밋은 했는데 GitHub에 아직 안 올렸다git push
빨강은 "아직 안 담음", 초록은 "담음", clean은 "끝". 이 세 가지만 구분하면 된다.

6. GitHub에 올리기 (첫 1회)

1
GitHub 계정 만들기. github.com에서 Sign up. 아이디는 이력서에 들어갈 수 있으니 장난스럽지 않게. 이미 있으면 건너뛴다.
2
저장소 만들기. 로그인 후 오른쪽 위 + → New repository. 이름은 예를 들어 ai-soc-course. Public(공개)으로 하면 포트폴리오로 바로 쓸 수 있고, 부담되면 Private로 시작해서 나중에 바꿔도 된다. "Add a README file" 체크는 하지 않는다(이미 내 PC에 파일이 있으므로). Create.
3
내 PC 저장소에 GitHub 주소 연결. 만들어진 페이지에 나오는 주소(https://github.com/아이디/ai-soc-course.git)를 복사해서: 
git remote add origin https://github.com/아이디/ai-soc-course.git
git remote -v        ← 주소가 두 줄 나오면 연결 성공
4
첫 push. 처음 한 번만 -u origin main을 붙인다. 그다음부터는 git push만 치면 된다. 
git push -u origin main
브라우저 창이 뜨면서 GitHub 로그인을 요구한다. 로그인하면 자동으로 이어진다.
5
확인. 브라우저에서 저장소 페이지를 새로고침하면 내 파일들이 보인다. 이 주소가 곧 포트폴리오 주소다.
공용 PC에서는 GitHub 로그인 정보가 이 PC에 남을 수 있다. 9번 참고.

8. 실수했을 때

엉뚱한 파일을 add 해버렸어
장바구니에서만 빼면 된다. 파일은 그대로 있다.
git restore --staged 파일이름
커밋 메시지에 오타가 났어 (아직 push 전)
git commit --amend -m "고친 메시지"
파일을 잘못 고쳤는데 마지막 커밋 상태로 되돌리고 싶어
아직 add도 안 한 상태라면:
git restore 파일이름
이건 정말로 내가 고친 내용이 날아간다. 되돌리고 싶은 게 맞는지 한 번 더 생각하고 친다.
push가 거부됐어 (large file / exceeds 100MB)
큰 파일이 커밋에 들어간 것이다. 그 파일을 .gitignore에 추가하고, 장바구니에서 뺀 뒤 다시 커밋한다. 이미 커밋에 들어갔으면 Claude에게 파일 이름을 알려주고 같이 푼다.
지금까지 뭘 저장했는지 보고 싶어
git log --oneline        ← 커밋 목록을 한 줄씩. q 를 누르면 빠져나온다
뭔가 꼬인 것 같은데 뭔지 모르겠어
git status 결과를 통째로 Claude에게 붙여넣는다. Claude Code에서는 명령 앞에 !를 붙이면(! git status) 결과가 바로 대화에 들어간다. 무슨 명령을 쳐도 파일이 지워지는 명령은 거의 없으니 겁먹지 않아도 된다.

9. 교육장 PC 주의사항

위험대처
PC가 초기화되면 폴더가 사라진다하루 한 번 push. GitHub에 있으면 다른 PC에서 git clone 주소 한 줄로 전부 되살릴 수 있다
다른 사람이 이 PC로 내 GitHub에 push할 수 있다이름/이메일은 --global 없이 폴더에만 설정. 하루 끝나면 Windows 자격 증명 관리자에서 github 항목 삭제(제어판 → 자격 증명 관리자 → Windows 자격 증명)
Claude 계정도 이 PC에 로그인돼 있다하루 끝날 때 Claude Code에서 /logout
Claude의 메모리(기억)도 이 PC에만 있다오래 갈 정보는 CLAUDE.md에 적는다. 그건 폴더 안 파일이라 GitHub에 같이 올라간다
